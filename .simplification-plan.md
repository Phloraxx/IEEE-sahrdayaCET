# Simplification working plan

## Delete or make inert

- Remove event organization/finance approval actions, approval gates, revision invalidation, and normal UI reads/writes. Keep the old PocketBase fields inert for forward compatibility and audit-history safety.
- Keep one event lifecycle command surface for publish, unpublish, and complete; retain separate transactional cancel/archive commands.
- Remove the unused `/api/app/events/{id}/coupon-preview` route, client helper, and compatibility tests. Keep unified `/pricing-preview` and transactional final pricing.
- Replace the user-facing 21-title role selector with Organizer, Finance, Registration Staff, Check-in Staff, and Content Editor; use one capability map with historical role aliases.
- Reduce redundant CI work: full integration on PRs into `dev` and final `main` pushes, a lighter merged-`dev` gate, no heavyweight repeat on `dev` → `main` PRs, and keep production SHA freshness/CD checks unchanged.

## Deliberately keep

- Scope checks, raw registration/payment read closures, finance-only money commands, append-only attendance/correction history, legacy event-level check-in, waitlist/cancellation/refund/certificate invariants, PayGate v4, public URLs, and curated public event presentation.
- Explicit notes/confirmation for unpublish, cancel, refund corrections, and archive.
- Historical role codes, organizational title/position fields, legacy payment evidence, and inert approval columns until a safe cleanup window.

## Compatibility and test impact

- New assignment commands accept canonical access roles and store existing scope-compatible role-code aliases; existing assignments continue to authorize through the same canonical capability map.
- Update clean-room role/lifecycle assertions to prove direct organizer publishing, paid-event publication without finance approval, finance-only money mutation, scanner redaction, and no coupon-preview route.
- Run focused unit tests, runtime syntax, lint, typecheck, full unit suite, production build, and the available clean-room/browser checks without touching live data or integrations.
