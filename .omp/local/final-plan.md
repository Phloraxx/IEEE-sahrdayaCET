## 1. HIGH — Fix 87 TypeScript type errors (`tsc --noEmit` fails)

**Files:** 23 files (full list below)
**What's wrong:** `tsc --noEmit` reports 87 errors. Type safety is broken; CI cannot use `tsc` as a gate.
**Root cause:** 5 categories of errors (react-hook-form resolver mismatch, `noUncheckedIndexedAccess` fallout, PB response typing, `getField` generic inference, misc).

### Fix plan (ordered by impact — fix the largest clusters first):

#### 1a. React-hook-form resolver type mismatch (42 errors — EventForm, ExecomForm, SocietyForm)
**Files:** `src/features/admin/EventForm.tsx`, `src/features/admin/ExecomForm.tsx`, `src/features/admin/SocietyForm.tsx`
**Fix:** Change `zodResolver(Schema)` to `zodResolver(Schema) as unknown as Resolver<FormValues>` (or use `z.infer<typeof Schema>` for the `useForm` generic instead of `z.output`). The cleanest fix is:
```ts
// Before:
const form = useForm<EventFormValues>({ resolver: zodResolver(EventFormSchema) })
// After:
import type { Resolver } from 'react-hook-form'
const form = useForm<EventFormValues>({ resolver: zodResolver(EventFormSchema) as Resolver<EventFormValues> })
```
**Effort:** 3 files, 1 line each. ~30 min.
**Risk:** Low — type-only change, no runtime effect.

#### 1b. `noUncheckedIndexedAccess` fallout (~20 errors — OverviewClient, EventsTableClient, ExecomClient, CustomFieldBuilder)
**Files:** `src/features/admin/OverviewClient.tsx`, `src/features/admin/EventsTableClient.tsx`, `src/features/execom/ExecomClient.tsx`, `src/components/admin/CustomFieldBuilder.tsx`
**Fix:** Add null checks on array access, or use non-null assertion `arr[i]!` where the index is guaranteed safe. For `getEventColor(index)` return type, add a fallback: `return colors[index % colors.length] ?? colors[0]!`
**Effort:** ~20 sites across 4 files. ~1 hour.
**Risk:** Low — defensive null checks.

#### 1c. PocketBase response typing (~9 errors — SocietiesClient, EventCard, EventDetailModal)
**Files:** `src/features/societies/SocietiesClient.tsx`, `src/components/EventCard.tsx`, `src/components/events/EventDetailModal.tsx`
**Fix:** The `Event.banner` type is `string | null` but code checks `typeof event.banner === 'object'`. Fix: update the `Event` interface so `banner` is `string | { url?: string } | null` (matching the PB expand shape), or change the check to `event.banner && typeof event.banner === 'string'`.
**Effort:** ~1 hour.
**Risk:** Low — aligns types with runtime.

#### 1d. `getField` generic inference (~4 errors — registration-service, check-in)
**Files:** `src/lib/registration-service.ts`, `src/routes/api/check-in.verify.ts`
**Fix:** Call `getField<string>(reg, 'registrationStatus', '')` explicitly so the return type is `string`, not the literal `''`.
**Effort:** ~10 min.
**Risk:** None — type-only.

#### 1e. Misc (~12 errors — admin.events.$id, admin.societies.$id, admin.execom, dates, route-helpers, others)

## 4. MEDIUM — Make webhook confirmation atomic

**File:** `src/routes/api/orders/webhook.ts:74-78`
**What's wrong:** `confirmRegistration()` and the `paymentStatus: 'paid'` update are two separate writes. A crash between them leaves `paymentStatus='pending'` permanently (idempotency guard blocks retry).
**Fix:** Combine into a single update:
```ts
if (isSuccess) {
  // Single atomic write — confirmRegistration logic inlined
  const reg = await pb.collection('registrations').getOne(registration.id, { fields: 'id,event,registrationStatus,ticketId' });
  if (!reg) return Response.json({ error: 'Registration not found' }, { status: 404 });
  const wasPending = getField(reg, 'registrationStatus', '') !== 'confirmed';
  await pb.collection('registrations').update(registration.id, {
    registrationStatus: 'confirmed',
    paymentStatus: 'paid',
    paymentData: body,
    ...(getField(reg, 'ticketId', '') ? {} : { ticketId: generateTicketId() }),
  });
  if (wasPending) await bumpEventCounter(getField(reg, 'event', ''), 'registeredCount', +1);
}
```
Alternatively, add `paymentStatus` as a parameter to `confirmRegistration`.
**Effort:** 30 min.
**Risk:** Low — same logic, just one write instead of two. Need to export `generateTicketId` and `bumpEventCounter` or move the logic inline.
